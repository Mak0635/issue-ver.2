# 講師用メモ

## 設計意図
- 3つの担当範囲（トップ / メニュー / 店舗情報）は `index.html` 内で十分に離してあり、
  間に空行を入れているため、**範囲外を触らなければ Git が自動マージできる**（コンフリクトしない）。
- 1ファイルにしたのは「同じファイルを3人で触っても、場所が違えば大丈夫」を体感してもらうため。
- 3つの Issue は難易度をそろえてある。
  - #1: 既存の文字・クラスの **書き換え**
  - #2: 既存のブロックの **コピー＆書き換え**
  - #3: 新しい要素の **追加**

## つまずきやすいポイント
| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `main` に直接コミットしてしまった | ブランチを切り忘れ | `git switch -c feature/...` で今の状態のままブランチを作れる（コミット前なら） |
| PR マージ後も Issue が閉じない | PR 本文に `closes #番号` がない／PR の向き先が main でない | PR 本文を編集して追記 or 手動で Close |
| 2人目の PR でコンフリクト | 担当範囲外（ヘッダーなど）を触った | 発展課題として解消を体験させるチャンス |
| カードが崩れる（#2） | `<div>` の開始・終了タグのずれ | インデントを揃えて対応関係を確認 |
| 色が反映されない | クラス名の打ち間違い（`bg-blu-500` など） | Tailwind ドキュメントで確認 |

## 発展（コンフリクト体験）
全員のマージ後、2人に「ヘッダーの `☕ Cafe` をそれぞれ別の名前に変える」Issue を同時に渡すと、
コンフリクト解消を体験できる。
